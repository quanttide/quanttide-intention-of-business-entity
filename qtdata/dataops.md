# 升级业务流程

量潮数据的业务围绕数据工程标准运转。标准已具备可发布状态（0.1.0），核心是分层结构与前置流程。

## 分层结构：规格层与实现层

数据工程标准分为两层：

- **规格层**：定义数据规格、数据契约、数据蓝图等关键概念，描述"数据应该是什么"
- **实现层**：承载工程上的具体实现细节

两层结构与整体工程定义风格统一，每个单元都有对应的组成。下一步是定义各种具体的组成，让标准更准确地表示工程细节。

## 前置流程：从需求到规格

1. 澄清 clarify：原始聊天记录/工作日志 → 数据需求文档 Requirement
2. 设计 design：数据需求文档 → 数据规格书 Specification

数据需求前置在数据规格之前：先澄清业务诉求，再设计数据规格。

## 交付流程

交付流程必须被严格规范并执行：以项目为容器，按"需求 → 规格 → 处理 → 交付"的流程运行，确保正式交付被执行到位，平台研发进度持续向前推进。

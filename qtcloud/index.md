# 量潮云体系

为什么要设计这么大一个平台体系？**因为需要把各种创新实践都装进去。**

公司在真实经营中持续产生制度发明与流程发明——发券、评审、议事、分包、记账、验收。这些发明若停留在群聊与默契里，会随人流失、无法规模化。每一种被验证的创新实践，都需要一个平台化的容器。各云不是先画蓝图再找场景，而是创新实践长出来之后，装进对应的云——平台体系是创新实践的收纳结构。

## 重演：实训基地的发明创新

实训基地自己的发明创新是整个体系最好的重演：成员在真实需求驱动下，独立发明了公司曾经发明过的制度——任务积分重演了代金券的雏形，自发分包重演了早期人工助研，多方评审重演了验收机制。

这种重演符合市场一般规律：同样的市场问题会催生同样的制度解。重演不是巧合，是验证——每当基地独立重演一项制度，就证明这项制度普适、可产品化。**复现即成熟。**

平台的研发方式由此确定：

1. **自由生长**：创新实践先在实训基地与社区的真实工作中运转，积累样本
2. **识别与命名**：被重演验证的制度要素，收进意图与洞察
3. **产品化装载**：固化为对应云的流程，成为平台的一等公民
4. **编排成整体**：各云以交付结果为协作单元、标准输入输出衔接，主站编排成完整流程——量潮云成为承载工作流程的唯一入口

## 各云分工

| 云 | 回答的问题 |
|----|-----------|
| 执行云 | 一个人的工作如何被验收（Outcome） |
| 众包云 | 超出个人产能的工作如何拆给多人完成（分包） |
| 数字资产云 | 知识与流程如何承载为数字资产，并展示其全景关联 |
| 写作云 | 大体量写作如何组织，让经验不随人断 |
| 创新管理 | 新工具与新方法如何探索市场边界，而非闭门自研 |
| 元工程 | 工作意图这类元资产如何生产与沉淀（AI 生成候选、人类整理校准） |

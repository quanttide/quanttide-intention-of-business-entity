# 量潮管理后台工作愿景

量潮管理后台（qtadmin）是企业治理思想和制度的平台化。它展示的不是功能，是治理方法。

## 定位：治理思想的平台化

qtadmin 不是一套管理系统的集合，也不再是"大杂烩"。

它承载的是量潮的治理思想——议事怎么设计（delib）、战略怎么发现（strategy）、资产怎么管理（asset）——这些思想在 qtadmin 中以系统化的方式被展示和执行。

## 与量潮云的分工

量潮云维持一整套所有人都能用的生产流程，管理后台强调企业的全局管理。

两者功能彻底分开：

- **量潮云**：生产工具。执行云承载任务流转，支持云承载工单响应，资产云承载数字资产。
- **qtadmin**：管理平台。所有生产工具都要剥离，它不再是生产工具，而是治理思想在系统侧的载体。

qtadmin 的视角首先是秘书处的管理视角。

## 封装独特思考方式

qtadmin 的核心目标是封装我们独特的思考方式。

比如"产教融合"这种思考模式，就是把所有在各个平台上的工作整合设计成"学习进度"。类似于这些思考方式，我们需要从实际流程之中找出来。

做法：

1. 从实际流程中提取模式（以某些灵感设计作为切入点）
2. 找到对应的数据
3. 让 AI 学习模式
4. 设计程序封装

这样，系统就会慢慢靠近我们想要的模式。这才是内部管理平台最大的作用所在。

## 从沟通语形成共识

沟通语里的讨论分散在群聊与单聊中，形成共识需要知识抽取的方法。知识提炼链已经落地为具体机制：

- **connect**：跨群搜索聊天记录，聚合分散的讨论
- **acquire**：LLM 从讨论中提取政策条目（name、description、source）
- **extract**：逐条抽取结构化本体（条款、执行步骤、可编码性），承载状态（settled/evolving/draft）
- **summary**：按主题归纳现有知识，忠实总结不越权

模糊（evolving）是政策演进中的合法承载状态，不强制澄清，随实践自然迁移。招聘与课堂的政策都从这条链路沉淀，这是「封装独特思考方式」的第一步落地。

培养目标也可以从交流中观察：创始人和股东代表对公司代表的重点培养，可以从创始人与公司代表的密集交流中看他们的话题重点，来看培养目标和培养方向。

## 内部资产管理

内部资产的核心建模点：

- 来自平台的原始数据定义为资产（assets）
- 人类操作分析的部分定义为 data
- 经过总结的信息和知识定义为 docs

每一个人一个 workspace。由此，内部资产、内部第二大脑、私有第二大脑按三层组织。

公开第二大脑作为私有第二大脑的元认知，进行开源和提炼；再通过经验结果反哺私有部分，整个系统就能不断提高效率。

这里承认一些隐形规则的存在，先把其中能显示的部分显示出来。随着平台升级，隐形部分会自然迁移到平台上。

工作案例是资产提炼的起点：CEO 直接介入管理时，把介入当作投资行为去建立工作案例。做完之后让 AI 总结记录，再用记录处理情况，就能得到高质量的工作案例。从工作案例提炼工作札记（适合挖掘方法论），从工作札记提炼工作手册（需要成套流程规则）和工程标准（可以建模，但需要中间过程）。

培训制度背后有培训 panel，panel 的角色信息需要被有效管理，就像管理招聘面试者和考核者一样——这是第二大脑的基本功能。

## 起步路径

从导出飞书和 GitHub 的数据开始，建立组织层面的分析工具，以此为出发点构建管理后台。

需要耐心：先把数据建模，再通过各种方法二次抽取，让数据更加有效。

## 演进方向

优惠券和代金券是未来代币的前身。现在就是用交付和知识资产作为底牌来发债。

这个体系能跑的前提是产能彻底突破瓶颈——不靠堆人，靠系统。
